# Cloud — контекст проекта

Self-hosted файловое облако (аналог Nextcloud по ядру функций): один Go-бинарник со встроенным SPA + PostgreSQL, разворачивается через `docker compose`.

## С чего начать в новой сессии
1. `docs/mvp-tasks.md` — **источник правды по прогрессу**: ✅ = сделано, дальше по порядку. Закончил задачу — отметь ✅ там же.
2. `docs/prd.md` — требования (R1–R20), цели и метрики, все принятые решения (таблица открытых вопросов Q1–Q11, решённые зачёркнуты).
3. `docs/architecture.md` — модули, схема БД, хранилище, WebDAV/WOPI, риски A1–A6.
4. Онлайн-копия PRD (Claude Docs): https://claude.ai/artifact/83EqZWEZqe4kKSG727ehSi — при изменении PRD обновлять и `docs/prd.md`, и её.

## Принятые решения (кратко)
- Go-бэкенд; редакторы через WOPI (OnlyOffice по умолчанию, Collabora опционально — профиль `collabora`); лицензия Apache 2.0.
- MVP-синхронизация — только WebDAV; свой десктоп-клиент — фаза 2, мобильный — фаза 3.
- Файлы хранятся «как есть»: на ФС — читаемое дерево (ключ текущей версии вычисляется из пути), в S3 — объекты по `blob_id`.
- Масштаб: 2 000 пользователей (~400 одновременно, ~10 млн узлов), бенчмарки на 20 млн.
- Миграция с Nextcloud не нужна. UI только на русском, но все строки через `t()` (`frontend/src/i18n`), бэкенд отдаёт коды ошибок.
- **Всё должно работать в Docker и подниматься `docker compose up -d --build`** — проверять изменения в запущенном контейнере, не только тестами.

## Соглашения (взяты из соседнего проекта `../chat` — образец стиля)
- Монорепо `backend/` + `frontend/`; модуль `github.com/do-service/cloud/backend`.
- Бэкенд: stdlib `net/http` (паттерны с методами), pgx/v5, goose (миграции `backend/internal/db/migrations/NNNN_name.sql`, встроены через embed), **SQL руками в `repo.go`, без sqlc/ORM**, конфиг только из env (`internal/config`), логи `slog`, ошибки API `{"code","message"}` через `internal/httpx`.
- Фронтенд: React 19 + TS strict + Mantine 9 + TanStack Query + react-router 7, vitest; коды ошибок в `src/api.ts` `ERROR_CODES` должны совпадать с `backend/internal/httpx` `Code*`.
- Комментарии на английском, объясняют «почему».

## Запуск и проверки
- Весь стек: `docker compose up -d --build` → http://localhost:8090. Первый админ: `ADMIN_USERNAME=admin ADMIN_PASSWORD=… docker compose up -d` на пустой базе (потом переменные игнорируются); вход — `POST /api/v1/auth/login`. OIDC-провайдеры и `SECRET_KEY` — в `cloud.env` рядом с compose (в `.gitignore`, формат — комментарий в `docker-compose.yml`); вход — `GET /api/v1/auth/oidc/{slug}/start`
- Dev: `docker compose up -d postgres` (127.0.0.1:55433, базы `cloud` и `cloud_test`), `cd backend && make run` (:8090, метрики :9091), `cd frontend && npm run dev` (:5173, прокси на :8090).
- Бенчмарк (E1-8): `bench/README.md` — `make bench-gen` (20 млн узлов в базу `cloud_bench`, ~4 мин, ~16 ГБ), `make bench-server` (:8091), `make bench-listing` / `bench-workday`, поиск — `bench/k6/search.js`; в CI — job `backend:bench` на 300k узлов.
- Десктоп для macOS: `cd desktop && make dmg` → `bin/Cloud-<версия>-macos-universal.dmg` (universal, ad-hoc подпись). Проверять `.app` запуском `open -n --env HOME=<tmp> --env CLOUD_TOKEN_STORE=file`.
- Проверки: `cd backend && make lint test`; `cd frontend && npx tsc -b && npm run test && npm run build`; WebDAV (litmus + rclone, ~20 с) — `cd backend && make test-webdav`.
- Keycloak для разработки: `docker compose --profile e2e up -d keycloak` (127.0.0.1:8180, admin/admin; realm `cloud` из `deploy/keycloak/realm-cloud.json`, пользователь ivan / ivanpass). E2e входа: `cd backend && make test-e2e` (в CI — job `backend:e2e`; тест сам создаёт и удаляет realm `cloud-e2e`).

## Подводные камни (уже наступали)
- Порт 8080 на машине занят dev-бэкендом chat → cloud на хосте использует **8090** (`CLOUD_PORT`).
- Директива `go` в `go.mod` (backend и desktop) — последний патч Go, но не новее образа `golang:1.27-alpine`: иначе сборка образа падает. GitHub Actions ставит ровно версию из `go.mod` (`go-version-file`), так что с новым патчем Go поднимать её — иначе CI собирает без исправлений безопасности. Сейчас 1.27.3.
- `/metrics` есть только на внутреннем порту 9090 (не опубликован); на публичном порту этот путь уходит в SPA.
- Ручная проверка OIDC с Keycloak в docker: issuer `http://keycloak:8180/…` должен совпадать для браузера и контейнера; у браузера мешают системный HTTP-прокси и HTTPS-апгрейд Chrome — проще пройти флоу curl-ом с `--resolve keycloak:8180:127.0.0.1 --noproxy '*'`.
- Рекурсивный CTE вниз по поддереву для массовых `UPDATE` ненадёжен: после массового изменения статистика отстаёт, и generic-план prepared statement выбирает nested loop по worktable — минуты на папке в 50 000 узлов. Для пометки поддерева идём по уровням (`updateSubtree` в `internal/fs/repo.go`, `parent_id = ANY($1)`).
- agent-browser не отправляет тела запросов больше ~20 МБ (буферизует их при перехвате через CDP): большие загрузки через UI в нём не проверить — проверять сервер curl-ом (`-T file`, не `--data-binary`), UI — файлами до ~10 МБ.
- WebDAV DELETE (и перезапись при MOVE/COPY) кладёт в корзину: прогон litmus или rclone против dev-базы оставляет там сотню элементов. Поэтому проверять `cd backend && make test-webdav` — отдельный сервер на одноразовой базе `cloud_webdav`; руками против dev-базы — потом чистить через `DELETE /api/v1/trash/{id}`.
- Консоль agent-browser не показывает нарушения CSP: проверять обработчиком `securitypolicyviolation`, повешенным через `eval`, и ходить по SPA без перезагрузки.
- OnlyOffice (редактор по умолчанию) ходит на WOPI-хост, только если тот назван в `IP_FILTER_RULES` (`allow cloud`; правило `*` не считается), и строит `urlsrc` в discovery из `Host` запроса — облако подменяет origin на `WOPI_EDITOR_URL` (`http://localhost:9981`). Новая версия появляется при закрытии документа и раз в 5 мин при правках (`autoAssembly` в `deploy/onlyoffice/local-production-linux.json`), а не по кнопке «Сохранить». После пересоздания контейнера docservice ~1–2 мин генерирует шрифты и перезапускается — документы, открытые в это время, падают.
- Collabora (опционально, `--profile collabora` + `WOPI_DISCOVERY_URL=http://collabora:9980/hosting/discovery WOPI_EDITOR_URL=`; `collabora/code`) — образ без shell: ключ подписи WOPI создаёт сервис `collabora-key` (alpine + openssl) в томе `collabora_proof`, без него Collabora не подписывает запросы. Collabora ходит к облаку как `http://cloud:8080` (`WOPI_HOST_URL`, `aliasgroup1`), браузер открывает его на `localhost:9980`. В agent-browser Ctrl+S в редакторе не сохраняет — жать кнопку сохранения.
- Git: ветка `main`; публичный репозиторий — https://github.com/do-service/cloud (модули `github.com/do-service/cloud/{backend,desktop}`). CI два: `.gitlab-ci.yml` (registry.exz-vps.ru) и GitHub Actions — `.github/workflows/ci.yml` (PR и main, образ `ghcr.io/do-service/cloud:edge`), `release.yml` (тег `v*` → multi-arch образ в GHCR + GitHub Release), `desktop.yml` (DMG в тот же релиз). Ни один пока не запускался на реальном сервере. Job webdav закреплён на `ubuntu-24.04`: `KNOWN_FAILURES` подобран под litmus 0.13.
- Десктоп на Linux: имя приложения на кириллице даёт GTK id `org.wails.wailsapp` — поэтому `Linux.ApplicationID` в `main.go`. В Docker WebKit стартует только не от root и с `--security-opt seccomp=unconfined --security-opt apparmor=unconfined --security-opt systempaths=unconfined` (иначе падает `bwrap`); плагину GTK у linuxdeploy нужен `dpkg-dev`.
- Десктоп на Windows (CI, Git Bash): `/S` превращается в путь `S:/` — писать `//S`, `//FI`; `makensis` не находит `File` с прямыми слэшами — пути с `\`, запуск с `-NOCD`; NSIS на `windows-2025` не предустановлен, choco иногда отдаёт 504 и выходит с кодом 0.
- Параллельные `make test` (несколько worktree) на общей `cloud_test` мешают друг другу — давать каждому свою базу через `TEST_DATABASE_URL`.
