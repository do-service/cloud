# Десктоп-клиент синхронизации (P1-1)

**Дата:** 2026-10-25 · **Статус:** проект согласован, задачи — [mvp-tasks.md](mvp-tasks.md), фаза 2 (E11–E15).

## Решения

| Вопрос | Решение |
|---|---|
| Платформы | macOS, Windows, Linux из одного кода; разработка и проверка сначала на macOS |
| Стек | Ядро на Go, окно и трей — Wails v3 (бета, закреплённая версия; в v2 нет трея), React в системном WebView |
| Модель v1 | В окне клиента — облако с миниатюрами; галочками выбираются файлы и папки, они синхронизируются в обе стороны в локальную папку. Неотмеченного на диске нет. При первом запуске ничего не отмечено |
| Фаза 2 клиента | Заглушки в Finder/Проводнике (File Provider, Cloud Files API, FUSE) поверх того же ядра и API |
| Вход | Только в браузере пользователя на домене самого облака (пароль, OIDC, 2FA — как в вебе); приложение пароль не видит и форм входа не рисует, получает токен устройства |
| Несколько облаков | Клиент подключается к любому числу инстансов (и аккаунтов на одном): у каждого подключения свой адрес сервера, токен, папка и состояние |
| Протокол | Свой API: журнал изменений с курсором, long-poll, загрузка через tus с докачкой, токен устройства через вход в браузере |
| Конфликты | Серверная версия остаётся под своим именем; локальная правка — «Имя (конфликт, Устройство, ГГГГ-ММ-ДД ЧЧ-ММ).ext», загружается на сервер |
| Подпись | Пока без подписи (Gatekeeper и SmartScreen предупреждают); Apple Developer ID — к фазе заглушек |

## Сервер

### Журнал изменений (E11-1)

Все записи в `nodes` идут через примитивы `internal/fs` (`insertNode`, `updatePlacement`, `replaceContent`, `markTrashed`/`unmarkTrashed`) — в них и пишется журнал, в той же транзакции. WebDAV, WOPI, загрузки по ссылке и Copy проходят через них же.

```sql
CREATE TABLE sync_heads (
  user_id    uuid PRIMARY KEY REFERENCES users ON DELETE CASCADE,
  tree_seq   bigint NOT NULL DEFAULT 0,  -- последний seq журнала его дерева
  min_seq    bigint NOT NULL DEFAULT 0,  -- всё <= min_seq удалено, курсор старее → 410
  access_seq bigint NOT NULL DEFAULT 0   -- меняется, когда меняется то, что он видит в чужих деревьях
);
CREATE TABLE sync_journal (
  owner_id  uuid NOT NULL REFERENCES users ON DELETE CASCADE,
  seq       bigint NOT NULL,
  node_id   uuid NOT NULL,      -- без FK: переживает purge
  op        smallint NOT NULL,  -- подсказка: create|content|move|trash|restore
  scopes    uuid[],             -- расшаренные узлы на старой и новой цепочке
  device_id uuid,               -- устройство-автор (fs.WithDevice)
  at        timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (owner_id, seq)
);
```

- **«Грязное множество», а не события:** строка говорит «узел X изменился в seq N»; `/sync/changes` дедуплицирует и отдаёт текущее состояние узла или tombstone. Перемещение — новая позиция, повторы безопасны.
- Поддерево при move/trash/restore папки не журналируется: клиент знает узлы по id. Папка, въехавшая в видимую область, помечается `subtree:true` — клиент дочитывает её через `/sync/tree`.
- Seq на владельца выдаётся внутри транзакции после `lockChains`, поэтому монотонен в порядке commit. `sync_heads` блокируется последней.
- Шаринг (`share.Grant/Update/Revoke`, членство в группах) переводится в транзакции и поднимает `access_seq` получателей.
- Хранение: задача `sync_journal_retention`, `SYNC_JOURNAL_RETENTION` (720h), поднимает `min_seq`. Старый курсор → 410 `cursor_expired` → полный ресинк по `sha256` без перекачки совпадающего.
- Цена записи: +1 INSERT, +1 индексный запрос к `shares` по цепочке, +1 UPDATE маленькой `sync_heads`. ~6 млн строк за 30 дней на целевом масштабе.

### API (`internal/sync`)

| Метод | Ответ |
|---|---|
| `GET /api/v1/sync/info` (без входа) | `{apiVersion, serverVersion, minClientVersion, journalRetention, maxWait}` |
| `GET /sync/roots` | свой корень и общие корни (`kind`, `name` «Имя (Владелец)» как в `webdav/shared.go`, `owner`, `permissions`, `etag`) и курсор |
| `GET /sync/tree?root=` | NDJSON всего поддерева `{id,parentId,name,kind,size,etag,sha256,mtime,permissions}`, обход по уровням (`parent_id = ANY($1)`), в одной `REPEATABLE READ` транзакции; первая строка — курсор |
| `GET /sync/changes?cursor=&limit=&wait=55` | `{changes:[{id, owner, deleted, node?, subtree?}], cursor, more, rootsChanged}`; 410 `cursor_expired` |

Курсор непрозрачный: `{v, own, a, s:{ownerId:seq}}`. Чужие деревья фильтруются по `scopes` и текущей видимости через `access`: ставший невидимым узел — tombstone.

**Long-poll (E11-4):** hub раз в секунду читает `sync_heads` (~2 000 строк) и будит ожидающих; соединение с БД ожидание не держит, работает на нескольких API-нодах. `wait` ≤ 55 с (меньше типичных 60 с у прокси), пробуждение с джиттером до 2 с: `min(2 с, 5 мс × число разбуженных разом)` — одно изменение доходит за ≤ ~1 с, сотни ожидающих расходятся по 2 с. Не LISTEN/NOTIFY (глобальная блокировка на commit) и не SSE (буферизация прокси). Пустой ответ (истекло `wait` или сервер останавливается) — обычный 200 с курсором: клиент сразу повторяет запрос с ним. Таймаут HTTP-клиента — больше `wait` (≈ `wait` + 15 с). Шаринг и членство в группах поднимают `access_seq` (E11-5) — это тоже будит ожидание, с `rootsChanged: true`.

### Условные записи (E11-3)

- tus: метаданные `nodeId` (замена по id), `ifMatch` (etag базы), `mtime`; ответ — `Upload-Node-Id`, `Upload-Node-ETag`; расхождение — 412 `precondition_failed` (новый код в `httpx` и `ERROR_CODES`).
- `If-Match` у `PATCH` и `DELETE /nodes/{id}`; `parentId` и `sha256` в DTO узла.

### Токены устройств (E12)

- Таблицы `devices` (имя, платформа, версия клиента, SHA-256 токена `cld_…`, `last_used_at`, `last_ip`) и `device_codes` (одноразовый код на 120 с, PKCE).
- Вход по RFC 8252, в системном браузере на домене облака (не во встроенном WebView: браузер уже знает cookie и пароли пользователя, а приложение не может подсмотреть ввод): клиент слушает `127.0.0.1:<порт>`, открывает `{server}/devices/authorize?…` — страница SPA за `RequireAuth` (пароль или OIDC через `?next=`), согласие, редирект с кодом; клиент меняет код и `code_verifier` на токен. `redirect_uri` — только loopback.
- Bearer в `auth.Middleware` с ограниченной областью: не пускать в `/admin/*`, пароли приложений и чужие устройства. Отзыв — в `/settings` → «Устройства» и в админке. Аудит `device.authorize/revoke/signout`, новый субъект в `security_test.go`.

## Клиент

### Пакеты (`desktop/`, модуль `github.com/do-service/cloud/desktop`)

```
cmd/cloud-desktop/   приложение Wails (окно + трей)
cmd/cloudsync/       CLI: sync --once/--watch, status — для тестов и до готовности UI
internal/api/        REST, /sync/*, tus с докачкой, скачивание с Range/If-Range
internal/signin/     loopback + PKCE, токен в Keychain / Credential Manager / Secret Service
internal/state/      SQLite (modernc.org/sqlite, без cgo), WAL, миграции
internal/localfs/    скан, file id, имена, игнор, атомарная запись
internal/watch/      FSEvents (cgo) на macOS, inotify на Linux, ReadDirectoryChangesW на Windows
internal/engine/     зеркало, сверка, план, исполнитель, конфликты, выбор
internal/app/        биндинги Wails, трей, автозапуск
frontend/            Vite + React + Mantine, алиас @web → ../../frontend/src
```

- `engine/api/state/localfs` не импортируют Wails: тесты идут с `CGO_ENABLED=0`.
- Go-код с бэкендом не общий (там всё `internal/`); контракт держат интеграционные тесты против настоящего сервера и общие golden-векторы имён.
- fsnotify на macOS — kqueue (дескриптор на файл, без рекурсии), для больших деревьев не годится; FSEvents ещё и отдаёт события «с id N» после перезапуска.
- **Подключения.** Подключение = адрес сервера + пользователь; их может быть сколько угодно, к разным инстансам и к одному под разными пользователями. У каждого свой id, токен в keyring (ключ — адрес сервера и id пользователя), своя папка (по умолчанию `~/Cloud/<имя сервера>`; папки подключений не могут вкладываться друг в друга) и свой движок. Адрес нормализуется (схема, хост, порт, без завершающего `/`) и проверяется через `/sync/info` до входа; http разрешён только для localhost.
- Состояние — вне синк-папки (`~/Library/Application Support/Cloud/<подключение>/state.db` и аналоги); в корне папки маркер `.cloudsync`. Нет маркера (диск отключён) — синхронизация стоит, удаления не распространяются.

### Движок

- **Удалённо:** `/sync/roots` → `/sync/tree` выбранного → цикл `/sync/changes?wait=55`; 410 → ресинк.
- **Локально:** скан при старте, события вотчера с задержкой 1–2 с, рескан раз в час и при переполнении очереди. sha256 — только если изменились size, mtime или file id.
- **Сверка трёх состояний** (база, локальное, удалённое) по node id и по пути и file id:

| Локально \ удалённо | без изменений | изменён | удалён | перемещён |
|---|---|---|---|---|
| изменён | загрузка `nodeId+ifMatch` | одинаковый sha256 → обновить базу, иначе конфликт | загрузить как новый (правка сильнее удаления) | перенести локально, загрузить |
| удалён | `DELETE If-Match` (в корзину) | скачать заново | убрать из базы | удалить на сервере с If-Match |
| перемещён | `PATCH If-Match` | переместить и скачать | загрузить как новый | позиция сервера сильнее |

- Локальное удаление папки: файлы по одному с If-Match; неизвестные на сервере дети скачиваются, папка «возвращается».
- **Имена:** сравнение по ключу сервера (`ToLower(NFC)`, `fs/names.go`). На macOS имя на диске — как вернул readdir, смена регистра — через временное имя. Запрещённые в Windows имена не скачиваются, видны в «Проблемах». Симлинки пропускаются; игнор `.DS_Store`, `Thumbs.db`, `~$*`, `.~lock.*#`, `*.tmp`, `*.part` и т. п.
- **Передачи:** загрузка после 3 с стабильного size/mtime; tus с докачкой после перезапуска. Скачивание в `.~cloud-<id>.part` с `Range`/`If-Range`, проверка sha256, fsync, rename. В файл пользователя не пишем на месте.
- **Сбои:** намерение в `ops` → действие → база и удаление `ops` одной транзакцией; операции идемпотентны.
- **Защита:** больше 500 файлов или 30 % выбранного исчезло за проход — пауза с вопросом.
- **Нагрузка:** 3 крупные + 8 мелких передач, ограничение скорости, бэкофф с `Retry-After`; 423 — повтор до 30 мин, 507 — в «Проблемы».

### Выборочная синхронизация

Правила include/exclude на node id, действует ближайшее вверх по цепочке, у корня по умолчанию exclude. Отмеченная папка — всё поддерево, включая будущее. Папки на пути к отмеченным — контейнеры: есть на диске, новые дети в них не приходят. Новое локальное получает include. Снятие галочки: догрузить несохранённые правки, удалить только совпадающее с базой, остальное — в «Проблемы». Перед отметкой — проверка места на диске.

### Общие папки (E13-9)

`~/Cloud/Доступно мне/<Имя (Владелец)>/…`, имена как в `webdav/shared.go`. В шарах только для чтения файлы read-only; локальная правка в них — конфликтная копия, не загружается.

### Интерфейс

- Трей: значки (синхронизировано, идёт, пауза, офлайн, ошибка), статус, «Открыть папку/окно/в браузере», пауза, выход.
- Окно: список подключений и «Добавить облако» (адрес сервера → проверка `/sync/info` → «Войти через браузер» открывает страницу облака, приложение ждёт возврата с отменой), у каждого подключения — выбор папки (не внутри iCloud/OneDrive/Dropbox), обзор облака с галочками в трёх состояниях и статусами, активность, проблемы, настройки.
- Веб-код переиспользуется: `/api/*` в `AssetOptions.Handler` проксируется на сервер с Bearer, поэтому `api.ts`, `files.ts`, `preview.ts`, `i18n`, тема работают как есть. В `FileList` — слот для чекбокса и статуса. Строки — ветка `desktop.*` в `frontend/src/i18n/ru.ts`.

### Задел на заглушки

Ядро разделено на удалённое зеркало и `Materializer` (v1 — полные файлы). `/sync/changes` подходит как якорь `enumerateChanges` File Provider, `/content` с Range — для гидрации, `/preview` — миниатюры. Расширение File Provider — Swift, связь с ядром через XPC или сокет; ядро без глобального состояния.

## Тесты

- Сервер: табличный тест журнала на каждый метод записи; property-тест «случайные операции через `fs` → зеркало из `/sync/changes` совпадает с деревом» — ловит будущий путь записи без журнала; клетки security matrix.
- Клиент: тест на каждую клетку матрицы сверки; stateful property-тест (`pgregory.net/rapid`) с memfs и фейковым сервером — после затишья локальное = удалённое, ничего записанного не потеряно, нет пинг-понга; fuzz имён и курсоров.
- Интеграция: два клиента и третья сторона через REST/WebDAV — конфликт, перенос 10 тыс. файлов, офлайн, 410 → ресинк, отзыв устройства, 5 ГБ с `kill -9`, 423, 507.

## Риски

- Корректность движка — главный: property-тесты в M1 и догфуд через `cloudsync` до UI.
- Журнал держится на том, что все записи идут через примитивы `fs`: правило в architecture.md и тест «воспроизведение».
- Wails v3 — бета: спайк в E13-1, версия закреплена.
- macOS: TCC-разрешения для `~/Documents` и `~/Desktop`; синк-папка внутри чужого облака запрещена.
