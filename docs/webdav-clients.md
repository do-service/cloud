# E7-5. Совместимость WebDAV-клиентов

Адрес для клиентов: `https://<облако>/dav/files/<логин>/`. Алиас для клиентов Nextcloud: `/remote.php/dav/files/<логин>/`. Вход — логин и **пароль приложения** из «Настроек», обычный пароль не подходит.

## Автоматически: litmus и rclone

Скрипт: `backend/scripts/webdav-compat.sh`.

- В CI это job `backend:webdav`: сервер собирается из исходников, база своя.
- Локально — `cd backend && make test-webdav` (нужен `docker compose up -d`). Команда поднимает отдельный контейнер `cloud-webdav` из образа compose на одноразовой базе `cloud_webdav`, прогоняет проверки и всё удаляет. Корзина dev-аккаунта остаётся чистой. Прогон занимает около 20 с.

**litmus** запускается по одному набору за раз (basic, copymove, props, locks, http), потому что сам он останавливается на первом наборе с падением.

- Падение вне списка `KNOWN_FAILURES` валит проверку.
- Если тест из этого списка начал проходить, скрипт пишет «now passes», и его пора убрать из списка.

Результат на 2026-10-25:

| Набор | Итог | Известные падения |
|-------|------|-------------------|
| basic | 16/16 | — |
| copymove | 13/13 | — |
| props | 29/30 | `propfind_invalid2`: тело с неверным объявлением namespace принимается (207 вместо 400). Безвредно, это известный пункт FAQ litmus |
| locks | 33/34 | `lock_shared`: shared-блокировки не поддерживаются (501). Клиенты, которые мы целим, берут exclusive |
| http | 4/4 | — |

**rclone** (`vendor=other`) работает с деревом, в котором есть кириллица, пробелы, эмодзи, `#%&+` в именах, вложенность в 5 уровней и файл на 50 МБ. Проверяются:

- `copy`, затем `check` и `check --download`;
- `sync` после изменения, добавления и удаления файла;
- `moveto` папки.

Любое расхождение валит проверку. Заливку 1 ГБ (пик памяти ~47 MiB, см. [webdav-spike.md](webdav-spike.md)) в CI не повторяем.

## Вручную перед релизом

Подключение и пароль приложения — как в «Настройках». На каждом клиенте пройти все шаги и записать результат в таблицу: ✅, ❌ с описанием или — если шаг клиент не умеет.

1. **Подключение:** адрес, логин и пароль приложения. Неверный пароль даёт отказ, а не зависание.
2. **Листинг:** корень и папка «Доступно мне». Размеры и даты совпадают с вебом.
3. **Загрузка:** маленький файл и файл больше 100 МБ. После загрузки он есть в вебе с тем же размером.
4. **Скачивание и открытие** файла, в том числе большого.
5. **Кириллица и эмодзи** в имени при создании, переименовании и обратно.
6. **Новая папка, переименование, перемещение** между папками.
7. **Удаление:** файл попадает в корзину веба.
8. **Правка на месте:** открыть текстовый файл с диска, изменить и сохранить. В вебе появляется версия, временных файлов (`~$…`, `._…`) в листинге не остаётся.
9. **Квота:** у клиента, который её показывает, видно свободное место.
10. **Только чтение:** в папке, расшаренной на чтение, запись отклоняется понятной ошибкой.

Особенности клиентов:

- **Windows (Проводник, «Подключить сетевой диск»).**
  - WebClient по умолчанию отдаёт Basic-пароль только по HTTPS (`BasicAuthLevel=1`), поэтому проверять на облаке с TLS.
  - WebClient не скачивает файлы больше ~50 МБ (`FileSizeLimitInBytes`, по умолчанию 50 000 000). Шаги 3–4 с большим файлом упадут без правки реестра — это ограничение клиента, его нужно записать в инструкцию.
- **macOS Finder** («Подключение к серверу», ⌘K). Finder пишет `._*` и `.DS_Store` и ставит блокировки. Шаг 8 проверять в TextEdit.
- **Linux.**
  - GNOME Files: «Другие места» → `davs://<облако>/dav/files/<логин>/`.
  - davfs2: `mount -t davfs`. У него свой кэш, поэтому изменения из веба видны после `umount`/`mount` или по истечении кэша.
- **Android.** Material Files или Solid Explorer: «Добавить хранилище» → WebDAV.
- **iOS.** Приложение «Файлы» WebDAV не умеет (только SMB). Проверять через Documents (Readdle) или FE File Explorer.
